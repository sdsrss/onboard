# v3.0.0-rc.1 · C1 SKILL.md 浅拆 spec

## Goal

把 SKILL.md 中 3 个最重的独立大块抽到子文件，降低 SKILL.md 单体行数与 consumer LLM 在长 spec 中"忘前段"的理论风险；同时保持 consumer 默认加载契约（SKILL.md 自动加载 → 进入对应 phase 时 prose 触发 sub-file Read）。

被抽出的 3 块：
1. `## Phase 7 · Claude Code Hooks` (SKILL.md:1327-1785, 458 行) → `skills/onboard/phases/phase-7.md`
2. `## Uninstall Mode（v2.8 新增；v2.11 三层模型 + 双模式重写）` (SKILL.md:2090-2298, 208 行) → `skills/onboard/phases/uninstall.md`
3. `## 状态文件结构（v2.9 schema）` (SKILL.md:2332-2459, 127 行) → `skills/onboard/references/state-schema.md`

预计 SKILL.md 从 2490 行降至 ~1700 行 (-31%)。

- **不**拆 Iron Laws / 元规则 / Marker conventions / Snapshot protocol — 这些跨整条 spec 引用，留在 SKILL.md。

- **不**改 consumer LLM 的执行流 — `/onboard` Phase 0-8 顺序、行为、Iron Law 触发条件全部保留。
- **不**做 Phase 7 之外的 hook 行为优化、Doctor mode 扩展、新增 D 检查、phase 4.5 build validation 等。
- **不**接 doctor mode D 检查到新的 validate-state.sh（已在 v2.12.0 spec 留 deferred）。

## Constraints

### C1. Sentinel + summary 约定 (HARD)

被抽出的 3 个 section 在 SKILL.md 原位置 **保留 header + 一句话摘要 + Read 指令**，以满足：

- consumer LLM 进入对应 phase 时按 prose 指令 `Read skills/onboard/phases/phase-7.md` 才能拿到完整 spec；
- 外部引用 (CLAUDE.md "Phase 7", README "Phase 7 hooks 必需 jq", `mirror-hooks.sh` 注释 "Safe to invoke from Phase 7") 不需要改 — 引用名字而非行号；
- 测试 `tests/integration/uninstall-modes.sh:49` 的 `grep -qE '^## Uninstall Mode.*v2\.11 三层模型'` 仍能命中 SKILL.md 中保留的 header；
- 测试 `tests/integration/uninstall-modes.sh:88` 的 prose-grep（检查 `.claude/onboard-keeper/hooks/` 出现）需要补：要么改成 grep SKILL.md OR `skills/onboard/phases/uninstall.md`，要么 SKILL.md summary 段保留这一关键路径名。

**Sentinel 形态**（示例 — Phase 7）：

```markdown
## Phase 7 · Claude Code Hooks

> 完整 spec 见 [`phases/phase-7.md`](phases/phase-7.md)（458 行）。Consumer Claude：进入本 phase 前必须 Read 该文件以获取完整 settings 模板 / 模式分支决策表 / hook canonical 示例脚本 / Iron Law 12/15/16/19/23 在 hook 层面的具体绑定。

本段保留要点（不替代 sub-file）：
- 由 settings.json 形式 (skill / command) × 模式 (local-only / share) × 安装来源 (plugin / user-skill / project-skill / command) 三维决定 hook 路径与脚本归属
- 4 个 hook：guard-bash (PreToolUse:Bash) / guard-edit (PreToolUse:Edit|Write|MultiEdit) / post-edit-check (PostToolUse) / stop-verify (Stop)
- jq 是 Phase 7 强依赖 (Phase 0 仅 warning，Phase 7 blocking)
- Iron Law 15 (exit 0 + stdout JSON XOR exit 2 + stderr) 绑定 4 个脚本
- Plugin 模式下默认通过 `skills/onboard/scripts/mirror-hooks.sh` 镜像到 `~/.claude/onboard-runtime/hooks/`
```

Sentinel 段保留要点（4-8 bullets）是为了让 consumer LLM 哪怕不 Read sub-file 也能做基本判断（防 sub-file Read 失败 fail-open），但**不替代**完整 spec —— 任何细节决策必须 Read sub-file。

## Open questions

1. **Sub-file 是否 share SKILL.md frontmatter（`disable-model-invocation: true` 等）？** — Skill 框架只读 SKILL.md frontmatter；sub-file 不需要 frontmatter，但顶部 1 段 "本文件是 X 的完整 spec" prose 是给 consumer LLM 看的。**默认决议**：sub-file 无 YAML frontmatter，只有 prose 引言段。
2. **Plugin install 时 sub-file 是否随 SKILL.md 自动 copy？** — 是。`install.sh` 已用 `cp -r skills/onboard/* <target>/`（v2.10 redesign）；sub-file 在 `skills/onboard/phases/` 和 `references/` 下自动跟随。无需改 install.sh。需要 verify (test 加 1 assertion: sub-file 在 install target 出现)。
3. **rc1 → 3.0 的 dogfood gate criterion？** — 跑 `/onboard --update` on 1 个真实 target project（gsd-lite 或干净 fixture），手测 consumer LLM 是否会按 prose 触发 sub-file Read。**默认决议**：dogfood pass + 0 "consumer LLM 忘 Read sub-file" 故障 = ship 3.0；否则改进 sentinel 段 → 重测。
4. **元规则编号要不要加 27 描述拆分契约？** — 应该加。"元规则 27（v3.0 sub-file 拆分契约）：sentinel header + summary 必保留在 SKILL.md；canonical spec 在 sub-file；改一处需 audit 另一处的 anchor 一致性。" 拆 commit 时同步加 CLAUDE.md 描述。
