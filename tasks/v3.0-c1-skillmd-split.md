## 3-view inline critique (Step 3)

**CEO view (用户价值 / time-to-value)**：

C1 浅拆 ROI 是 *理论性* 的 —— memory 已 record "0 条 consumer 投诉" + "理论焦虑无实测"，这次启动的唯一现实理由是 prior-AUTH 优先性 (§3 TRUST)。但 ROI 其实有一个 *未被 surface 的次级好处*：sub-file 边界让"维护一个 458 行 Phase 7 段"变成"维护一个独立 phase-7.md 文件"，后续给 Phase 7 加新内容（如未来 hook 新 matcher、新 install source 检测）触动面更小、blame/diff 更清晰。但代价是 sentinel summary 漂移风险（C1 spec 显式标 HARD），需要元规则 27 + 测试断言夹住。**净评**：浅拆是低风险锚定动作，但不应膨胀到中拆/深拆 —— 闸门 1/2 仍 active。

**Design view (consumer LLM 执行流)**：

核心 design tension：consumer Claude 默认只 auto-load SKILL.md；sub-file 必须显式 Read。浅拆方案的 mitigation 是 *双层保护*：(a) SKILL.md sentinel summary 给基本决策依据，(b) sentinel 段含 `Read .../<sub-file>.md` 明确指令。如果 consumer Claude 在 Phase 7 entry 时 *跳过* sub-file Read 直接用 summary 做决策 —— 这是 design risk。Mitigation：sentinel summary 必须明确 "本段不替代 sub-file"，且 "完整 settings 模板" / "canonical 示例脚本" / "Iron Law 15 hook 层绑定" 等 actionable 内容只在 sub-file，使 consumer 在第一次需要查 actionable 细节时就被迫 Read。**风险评级**：MED；可通过 T19 dogfood 验证。

**Eng view (实现 + 维护成本)**：

机械抽取（`awk NR>=1327 && NR<=1785`）+ frontmatter 注入 + sentinel 改写 = 30 min。Tests assertion 增量 (~9 个) = 20 min。Cross-cutting grep + audit fix = 30 min。Release commit + preflight + push = 15 min。总预算 ~100 min，合理。最大风险：T6 SKILL.md 三段 Edit 的 `old_string` 唯一性 —— 3 段每段几百行，需用 header + 后续 5-10 行做 anchor。若 Edit 失败，回退方案是用 `sed` 删除 + `cat` 注入，但破坏性大；首选确认 Edit anchor 唯一。**净评**：复杂度集中在 SKILL.md 3 段 Edit + cross-cutting grep；rc.1 是必要 hedge（不直接 ship 3.0）以便有一次 dogfood 修复窗口。
